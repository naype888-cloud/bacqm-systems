Measured, not assumed

Every figure on this site comes from instrumentation at the kernel–hardware interface, under real work. Differences are taken against a baseline that is the same kernel with nothing of ours loaded (E1); shapes are taken on the deployed system itself (E2–E4). The probe never adds load to flatter itself: what the system does while it is observed is what it does.

E1A/B campaigns against the baseline

Protocol. CONTROL is the unmodified kernel with its default fair scheduler. Each campaign alternates CONTROL and BACQM on the same node, n≥3 runs per arm, and reports the median. A campaign counts only if the thermal state stays within 5 °C across its runs; two campaigns failed that test and are excluded.

The step of 26 September · non-invasive measurement

Until 26 September a system thread woke every 1 ms, the same period as the probe, and that favoured the probe. Since then it sleeps when there is no work and no longer perturbs the system. An A/B on 15 October with the same module confirms it: with the 1 ms pulse the probe reads p99 = 159 µs, without it 280 µs. We do not perturb the system to improve a measurement, so the second interval is the one that stands; missed cycles fell from 0.080 % to 0.013 % across the same step. These figures describe the probe, not a workload.

E3Saturation of the fast domain

Workload. A real-time graphics pipeline whose resident set exceeds the fast domain, run as a user plays it: seven runs on 23–24 Oct 2026, 425,860 frames, 133 minutes. It is chosen because it drives s=‖σ‖𝒱/C𝒱 to the boundary (maximum 0.9984) while the accelerator runs near full duty: the regime in which (1.1) predicts a discontinuity.

Observable. The frame period τf, recorded per frame by an in-process overlay, in units of the presentation period T0=1/60 s. Occupancy, accelerator duty and host load are recorded on the same frame and enter only as ratios. Arm. Single arm, BACQM active: this campaign tests the shape of qp(s) near s=1, not a difference against CONTROL (that is E1). Kernel log over the seven runs: no panic, no out-of-memory action, no guard termination.

E5Extreme-entropy asymptotic allocation

Workload. An unconstrained symbolic proof-resolution pipeline executing deep recursive dependency search over an extensive axiomatic corpus, operating continuously for >60 minutes (2 Nov 2026). The active resident set exceeds 20 % of total host memory (>6.5 GiB in a single task tree), accompanied by concurrent asynchronous dirty-page writeback workers.

Observable. Run-queue scheduling delay (p50,p90,p99,p99.9) sampled at 60-second intervals via non-invasive eBPF scheduler probes (sched_ext with the nava operator manifold), memory pressure stall duration (PSImem), and directional page transport flux (pswpin,pswpout).

Dynamic invariance under extreme saturation · non-heuristic regulation

1. Microsecond median under load 9.25: Conventional schedulers experience priority inversion and tail explosion under memory-induced writeback stalls. Here, the scheduler's median dispatch delay remains locked between 1 µs and 12 µs throughout the entire session.

2. Asymptotic zero-evacuation: Following an initial burst of 1.24×105 pages evacuated into the 7-way bundle, outward swap drops to strictly zero (pswpout=0) for over 30 minutes, preventing any swap-thrashing stall.

3. Zero-OOM safety: The invariant memory guard recorded zero liquidations (kills=0, danger=0), and the uncertainty bound remained certified on every tick.
